# ADR-0010: Portuguese / English internationalization

## Status

Accepted (specification); implementation not started

## Context

AACT’s Next.js UI is hardcoded European Portuguese (`lang="pt-PT"`), while the Laravel API returns mostly English validation and domain messages, and two queued notifications are hardcoded Portuguese. There is no locale negotiation, no user language preference, and no shared FE/API i18n contract. The product is an authenticated admin/portal tool behind a same-origin Nginx gateway, with stable invitation deep links.

Full analysis and phased plan: [I18N_IMPLEMENTATION_PLAN.md](../I18N_IMPLEMENTATION_PLAN.md).

## Decision

1. **Locales:** application tags `pt` and `en`; default **`pt`**; Intl / `html lang` map to `pt-PT` and `en-GB`.
2. **Web:** adopt **next-intl** with **`localePrefix: 'never'`** (cookie-based locale, no URL prefix).
3. **API:** Laravel lang files + `Accept-Language` middleware; respond with `Content-Language` and `Vary: Accept-Language`.
4. **Responsibility split:** UI chrome, enum labels, and help on the web; validation grammar and email copy on the API; stable error **`code`** values for domain/authz (web maps codes to strings).
5. **Persistence:** add `users.preferred_locale`; do **not** introduce multilingual tables for business names or help; do **not** mass-rewrite historical English `status_reason` / ledger text—prefer optional reason codes later.
6. **Client contract:** `apiFetch` always sends `Accept-Language` matching the active UI locale.

## Consequences

- Invitation and admin URLs remain path-stable.
- API clients that omit `Accept-Language` will receive Portuguese validation messages once `APP_LOCALE` defaults to `pt` (breaking vs today’s English defaults); the web must send the header.
- Two translation stores exist (next-intl JSON + Laravel PHP) by design; they must not duplicate the same ownership (chrome vs mail/validation).
- E2E tests that assert Portuguese copy need locale fixtures or stable test ids during implementation.
- Implementation follows the ten-phase roadmap in the plan document; this ADR does not ship catalogs or code by itself.
